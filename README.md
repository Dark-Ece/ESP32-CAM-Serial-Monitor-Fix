## 1. Project Overview

This repository documents a serial communication issue encountered while programming an AI Thinker ESP32-CAM using the CH340 USB-to-Serial adapter and PlatformIO IDE in Visual Studio Code.

The firmware uploaded successfully, but the ESP32-CAM stopped running normally when the Serial Monitor was opened.

This repository explains the symptoms, troubleshooting process, root cause and configuration-based solution.

## 4. Problem Description

The following issue was observed during development:

1. Firmware compiled successfully.
2. Firmware uploaded successfully to the ESP32-CAM.
3. The onboard white flash LED blinked when the Serial Monitor was closed.
4. When the PlatformIO Serial Monitor was opened, the LED stopped blinking.
5. The Serial Monitor displayed no readable output.

**Initial observation:** Firmware uploading worked correctly, but normal operation and serial monitoring were affected when the monitor opened.

## 5. Root Cause

The issue was associated with the DTR (Data Terminal Ready) and RTS (Request To Send) control signals generated by the CH340 USB-to-Serial adapter when PlatformIO opened the serial port.

These signals can interact with the ESP32's automatic reset and boot-mode circuitry.

## 6. Solution

The issue was resolved by disabling DTR and RTS control-line activation in the PlatformIO configuration.

The following lines were added to `platformio.ini`:

```ini
monitor_dtr = 0
monitor_rts = 0
```

### Final Working Configuration

```ini
[env:esp32cam]
platform = espressif32
board = esp32cam
framework = arduino

monitor_speed = 115200
upload_speed = 115200
monitor_filters = direct

monitor_dtr = 0
monitor_rts = 0
```

## 8. Key Learnings

This troubleshooting exercise provided practical understanding of:

- UART serial communication.
- USB-to-UART converters.
- CH340 USB-to-Serial adapters.
- DTR and RTS control signals.
- ESP32 reset and boot-mode behaviour.
- PlatformIO configuration.
- Embedded system debugging.

**Important lesson:** Successful firmware uploading does not necessarily guarantee correct serial monitoring or normal boot behaviour. USB-to-UART control signals can also affect microcontroller operation.
